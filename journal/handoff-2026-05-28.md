## Reference .tsx pattern (NEW doctrine — read this)

**Problem:** Mock PNGs are for human eyes. Claude Code reads them as images and reinvents Tailwind classes that look "close" but aren't pixel-exact. This caused two waves of visual drift in slices 2 and 3.

**Solution:** For any screen where visual fidelity matters, commit a `mocks/<Component>.reference.tsx` alongside the PNG. The reference is a full JSX tree with every Tailwind class, every inline style, every piece of copy, every SVG path locked. NOT imported by production. Exists only as a copy-paste source.

**How to use:**
- Slice prompts that touch a referenced screen MUST say "copy the JSX from `mocks/X.reference.tsx` verbatim into the production component, preserve behavior (state, effects, handlers, db reads), do not change any class or copy."
- If production drifts, run a "visual fidelity patch" slice that re-syncs by copying the reference back (slice 3.5 is the template).
- If the reference itself is wrong, fix the reference first, then re-run the patch.

## Failure modes to NOT repeat

1. **Interpreting layout from a PNG.** Don't. Use the reference .tsx files. If a screen has no reference yet, build the reference first, get Daniel approval, then implement.
2. **Inventing Tailwind classes that look "close."** `rounded-md` vs `rounded-2xl` is not interchangeable. `text-[11px]` vs `text-xs` is not interchangeable. Copy classes verbatim from references.
3. **Changing copy without permission.** "STICKERS TO FIND" is not "FWC 2026 Sticker Swap" even though both make sense for an eyebrow.
4. **macOS Screenshot filename trap.** `Screenshot ... at H.MM.SS PM.png` uses U+202F (NARROW NO-BREAK SPACE) between the time and "PM", not a regular space. String-matching breaks if you assume regular space. Use `os.listdir()` to get real bytes when scripting.
