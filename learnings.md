# Sticker Swap — Learnings

> Append-only. Newest at top. Project-level lessons that outlive any single session — design heuristics, process patterns, dead ends worth remembering.

## 2026-05-28 (Session 6 — Module 7 killer-feature reversal)

- **Mocks-as-authoritative.** For any feature where visual taste matters, commit a PNG to `mocks/` *before* slice planning. Slice prompts cite the PNG path; plan-mode reviews flag every deviation for Daniel approval before code is written; when spec prose and the PNG disagree, the PNG wins and the spec gets amended. Two rounds of drift in Module 7 made this load-bearing. Workflow: PNG → spec cites PNG path → plan cites both → execute → diff-review against PNG. Spec prose is mutable; PNGs are the lock.
- **`.reference.tsx` files defeat Tailwind-class drift.** PNGs alone don't solve fidelity — Claude reads a PNG as an image and *invents* Tailwind classes that are "close enough" but not the locked values (`rounded-md` vs `rounded-2xl`, `text-[11px]` vs `text-xs`). Mitigation: commit `mocks/<Component>.reference.tsx` — a full JSX tree with every class, inline style, copy, and SVG path locked. Production copies it verbatim; the reference file is never imported. When production drifts, a "visual fidelity patch" slice re-syncs from the reference. If the reference itself is wrong, fix the reference first, then re-run the patch.
- **§4.12 reversal at full-feature scale works — delete, don't deprecate.** A load-bearing decision (the entire killer feature + its `<50ms` performance contract) can be retired mid-project under doctrine §4.12, provided the reversal is captured in a spec + journal entry + CLAUDE.md rewrite. The trap to avoid: softening the reversal with vestigial code ("keep the Lookup folder, just unwired"). Delete the folder. The next session inherits a clean codebase rather than a graveyard, and `grep -r "old-feature" src/` becomes the canonical regression test.
- **Plan-mode context cap leaves a plan, not a partial execution — and a follow-up session can mistake one for the other.** Slice 4 hit Claude Code's context cap *during plan mode*, before any code ran. The follow-up session opened with a handoff file that said "slice running at handoff time" and with an early Glob result that returned no files for the lookup folder. Both signals were misleading — the plan never executed and the folder still existed; Glob just missed the folder for an unknown reason (filesystem race, iCloud sync state, or a relative-path bug). The misread nearly shipped a journal entry claiming "deletion landed in the Claude-Code leg" when nothing of the sort happened. Lessons: (1) handoff docs should distinguish "plan generated, awaiting approval" from "execution in flight" explicitly. (2) Before writing a journal entry that asserts a destructive op already happened, cross-check with `bash ls` — Glob alone is not a reliable destructive-op detector. (3) When a follow-up session inherits a "this is half done" framing, treat every claim about what's already done as a hypothesis until verified.

## 2026-05-26 (Session 5 — GitHub + Vercel launch + portfolio reorg)

- **Pre-init working-tree audit before any first commit.** Running `git init && git add .` blindly on a long-running pre-git project ships stale files to GitHub. Session 5's audit caught five: a macOS Finder duplicate (`vite.config 2.ts` — iCloud sync produces these), accidental TS compile artifacts of `vite.config.ts` (`vite.config.js` and `vite.config.d.ts`), TypeScript incremental cache (`*.tsbuildinfo`), and a personal-info leak (`.claude/settings.local.json` contained `/Users/danieltartaro/.claude/settings.json`). All would have made the public commit absent the audit. Add to standard pre-init checklist: build-artifact sweep, secret-pattern sweep, personal-info sweep, Finder-duplicate sweep — and bake the patterns into `.gitignore` rather than just deleting (so re-occurrence is impossible).
- **`gh auth login` is the right macOS GitHub auth path post-2021.** HTTPS-with-PAT-as-password was deprecated by GitHub in 2021 — pushing without setup returns "Password authentication is not supported." `brew install gh && gh auth login` walks through device-code browser auth in one round-trip and caches the PAT in macOS keychain via the `osxkeychain` credential helper. Subsequent `git push` against any GitHub repo on that machine works silently. Beats SSH-key setup (3+ steps + GitHub UI navigation) for solo developers on personal Macs. The `gh auth setup-git` step happens automatically during `gh auth login` when "Authenticate Git with your GitHub credentials" is answered yes.
- **Non-dev distribution requires a hosted URL, not a GitHub README.** Surface this question before any OSS launch comms — if the audience includes anyone who can't run `npm install`, the README's install path is a wasted touch. Deploying a static PWA on Vercel takes ~10 min (sign in with GitHub, import repo, auto-detect Vite, deploy) and unblocks every non-dev audience. Single principle: where the README's first install paragraph says "clone the repo," there's a missing hosted URL above it.
- **Reddit and FB audiences need different lead URLs.** Same project, two distribution surfaces, two primary links. Reddit's dev overlap leads with the GitHub repo (source + JSON gift); FB's parents/collectors lead with the hosted URL (open + Add to Home Screen). Don't homogenize launch comms across surfaces with different audience profiles. The mistake to catch: an unrequested "consistency" pass that overrides audience-fit. When proposing a same-edit-across-all-drafts change, the question is "which audience gets which framing?" not "are the drafts consistent?"
- **`base: '/'` Vite default = trivial Vercel root-domain deploy.** Subpath hosting (GitHub Pages serves at `username.github.io/repo-name/`) would have required `base: '/repo-name/'` in vite.config + asset rebuild + all PWA manifest paths re-resolution. Vercel's root-domain serving means zero code changes for first deploy. Pattern: when choosing a host for a Vite PWA built without subpath config, prefer root-domain hosting (Vercel, Netlify, custom domain on Cloudflare Pages) over subpath hosting (GitHub Pages on default project pages) to avoid the rebuild.
- **iOS Chrome can't install PWAs.** Chrome on iPhone is a Safari WebView wrapper; "Add to Home Screen" via the Chrome share sheet creates a Chrome-launched shortcut, not a true standalone PWA. Safari is the only iOS browser that produces a real standalone install. Install instructions for non-dev iPhone audiences must call this out explicitly — otherwise they'll try Chrome (their daily-driver), get a non-PWA shortcut, and the offline / install experience silently breaks.

## 2026-05-26 (Session 4 — Module 6 implementation, 4 slices)

- **Rasterizer matters for icon verification.** ImageMagick and sharp/librsvg interpret the same SVG differently — slice 3's chrome line rendered fine in ImageMagick but disappeared in `@vite-pwa/assets-generator`'s sharp pipeline (librsvg backend). Lesson: when verifying SVG-to-PNG output, render through the same pipeline that ships, not whatever rasterizer is convenient. Specific quirk caught: `<line stroke="url(#bbox-gradient)">` with default `gradientUnits="objectBoundingBox"` is undefined behavior on a degenerate (zero-height) line bbox — librsvg only renders at endpoints. The portable form is `<rect fill="url(#gradient)">` + `gradientUnits="userSpaceOnUse"` with explicit coords.
- **One-shot tools via /tmp scratch directories.** The `opentype.js` + `wawoff2` extraction of the Archivo Black "00" glyph ran in `/tmp/opentype-shot/` with an isolated `npm install`, produced inline SVG path data, then the script was discarded. `package.json` stayed clean. Reusable pattern for any "use a dep once, commit the output" workflow — much cleaner than landing a tool in devDeps when it'll never run again.
- **Smoke-driven slice expansion is the norm, not the exception.** Module 6 was planned as 3 slices. Slice 4 absorbed three on-device findings (variable card size, missing team stripes, stuck All-done state) in one ~30 min plan-mode session. Lesson: budget for an extra polish slice in any multi-slice module — smoke reliably surfaces 1-3 items the spec didn't anticipate, and rolling them into the same module is cheaper than carrying them as session-N+1 debt.
- **Push back when a plan "simplifies" by dropping existing UI.** Claude Code's slice 2 plan proposed removing the Lookup state pill because action-button labels carry state info ("Now I have it" implies NEED). That was a Module 4 re-decision (spec 03's "read + context-aware quick toggle" lock — the read is half the contract) disguised as a Module 6 simplification. Caught by tracing the existing `ResultCard` code back to its spec. Pattern: when a plan removes existing UI, ALWAYS trace what spec/lock created it before approving — silent simplifications are how prior calls get reversed without §4.12 scrutiny.
- **Pre-flight Tailwind utility resolution.** Slice 1 plan would have silently failed because `text-text-muted` couldn't resolve — only the `fifa-*` palette was being extended in tailwind.config.js, not the operational surface palette. Tailwind v3 drops unknown classes without warning, so the bug would surface as unstyled text on iPhone, not a build error. Pattern: when extending `theme.extend.colors`, audit ALL utility classes downstream consumers will use against the extended config — don't trust that "the colors are defined as CSS variables" is enough.
- **Chrome-line empirical revision: same identity, scale-appropriate weight.** Session 3's "multi-scale identity atom" learning said the chrome line is the same 2px stroke at every scale. Slice 3 disproved this empirically — 2px is sub-pixel at iOS home-screen render. The revised principle is more honest: same gradient *identity* (color stops, metallic character) at every scale, but with scale-appropriate weight. Icon scale needs 8px; in-app `<ChromeDivider>` stays at 2px. Generalizes: be wary of "same primitive at every scale" claims that haven't been smoke-tested at the smallest scale.

## 2026-05-26 (Session 3 — design system)

- **References-first beats vibe-first.** Asked "what's the design north star?" abstractly; Daniel correctly redirected to "let's discuss references first." Designers anchor on artifacts before vocabulary. The four FIFA refs (emblem, host poster, tri-host poster, Panini pack, definitive emblem) gave us 8 specific tokens we'd never have extracted from words.
- **Two-surface framing is the unlock.** Most design conversations get stuck choosing between "utilitarian" and "branded." Splitting into **operational surface** (high-touch, every-day, fast) and **brand surface** (low-touch, identity-defining, expressive) lets both coexist. Sticker-swap's icon lives on the brand surface; FirstInventory lives on the operational surface; the chrome line is the single atom that bridges them.
- **Multi-scale identity atoms multiply cohesion cheaply.** The chrome gradient line is the same atom at three scales: 2px on the 60×60 icon, 2px on the 175×340 phone viewport, 1.5px around shiny cards. One token does brand work at every scale. Pattern: when picking design primitives, prefer ones that scale to multiple contexts over ones that work at one size only.
- **4-option exercises drive faster decisions than open discussions.** Every locked decision came out of a 4-option mockup (typography, icon, action colors, layout, type pill, team affiliation, shiny indicator). Daniel made each call in <30 seconds of looking. The structure forces specificity and removes the "what about…" tail.
- **Use the session task list as a design tracker.** Tracking 8 decisions in a checklist (locked / in-flight / pending) prevented mid-session drift. Watch item flags (orange contrast, violet/Need collision) caught at lock-time get captured durably, instead of evaporating after the decision.
- **Watch items > re-decisions.** When a locked choice has a known risk (fifa-orange contrast at 3.2:1; LEGEND/Need both using fifa-violet), capture it as a watch item rather than re-opening the decision. Re-decisions are doctrine §4.12 violations; watch items are §4.2-aligned ("verify on real device, change if reality demands").
